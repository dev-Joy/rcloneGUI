# 002 제외 패턴 저장 · 골라 넣기

- 작성: Claude (사용자 메모 2026-10-22를 정리) · 상태: 완료
- 관련: F03(제외 패턴), F28(글자 수 제한)

## 문제

제외 패턴은 작업마다 편집 창에서 한 줄씩 직접 쓴다. 같은 패턴(`node_modules/**`, `.git/**`, `*.tmp` …)을 작업마다 다시 써야 하고, 사용자는 "작업 3개만 추가해 봤는데도 패턴 넣는 게 어렵더라"고 했다.

## 바라는 결과

- 한 번 쓴 패턴은 앱의 로컬 DB(`rclonegui.db`)에 **중복 없이** 저장된다. 작업을 저장할 때 그 작업의 패턴이 자동으로 들어간다.
- 새 작업 · 작업 편집 창의 제외 패턴 칸에 **[패턴 추가]** 단추. 누르면 저장된 패턴 목록이 **체크박스**로 나오고, 고른 것을 칸에 덧붙인다(이미 있는 줄은 다시 넣지 않음).
- 목록에서 패턴을 지울 수 있다(저장된 목록에서만 빠지고, 작업에 이미 들어간 패턴은 그대로).
- 처음 켰을 때 기존 작업들의 패턴을 한 번 모아 넣는다(지금까지 쓴 것이 바로 보이게).

## 영향

- DB 스키마 v3(`exclude_patterns` 표: 패턴 TEXT PRIMARY KEY, 처음 쓴 시각, 마지막 쓴 시각, 쓴 횟수). 작업 저장 경로(`clsJobStore.save`). 새 IPC(목록 · 지우기). 편집 창.
- 실행 · 필터 파일 생성과 무관(패턴 목록은 고르기 도우미일 뿐, 작업의 `excludes`가 그대로 진실이다).

## 제약

- 패턴 검사는 지금과 같다(F28: 한 줄 512자, 200줄, 줄바꿈 금지). 저장 목록도 같은 검사를 거친다.
- 실제 사용자 경로 · 패턴을 테스트에 넣지 않는다.

## 미해결 질문

- 없음. (자주 쓴 순으로 보이고, 이름순 정렬 단추를 둔다.)

## 계획

1. `app-database.ts` 스키마 v3, v2 → v3 이동 때 기존 작업 `excludes`를 모아 넣기(트랜잭션).
2. `src/main/store/pattern-store.ts` `clsPatternStore`: `list()`(쓴 횟수 · 최근 순), `remember(patterns)`(INSERT … ON CONFLICT 횟수 +1), `delete(pattern)`.
3. `clsJobStore.save` 뒤 `remember(job.excludes)`(작업 저장과 같은 트랜잭션).
4. IPC `patterns:list` · `patterns:delete`(zod: 패턴 문자열 검사).
5. 편집 창: [패턴 추가] → `PatternPickerDialog`(체크박스 목록, 검색 칸, [추가] · [취소], 각 줄 옆 지우기). 고른 패턴을 칸 끝에 줄로 덧붙이고 중복은 빼기.
6. 테스트: 스키마 이동(v2 DB의 작업 패턴이 모임), remember 중복 · 횟수, delete가 작업을 바꾸지 않음, IPC 검사.
7. 증명: `pnpm run check`, app-verifier가 작업 2개에서 패턴을 저장 → 세 번째 새 작업에서 체크해 넣기 → 저장 → 비교에 반영되는지.

## 결과

- 2026-10-22 구현, reviewer · app-verifier R3 통과. 명세 `docs/specs/2026-10-22-exclude-patterns.md`. 버튼 이름은 [저장된 패턴에서 추가]. 함께 고친 것: 대화상자 위 대화상자에서 Esc · Tab은 맨 위 것만, 닫으면 연 단추로 초점 반환(모든 대화상자).
- 남은 것: 열린 직후 상자에 초점이 있을 때 Shift+Tab 한 번이 뒤 화면으로 빠질 수 있음(정적 검토 의견, 화면 확인에서는 재현 안 됨). v2 → v3 이전은 단위 테스트로만 확인(화면 검증은 늘 새 프로필).
