# 021 자동 실행 1단계 (앱 안)

## 문제

정해진 시각마다 동기화를 손으로 눌러야 했다. 자동으로 돌리면 사람이 확인하지 않은 삭제가 일어날 수 있다.

## 바라는 결과

- 작업별 간격 · cron으로 앱 안에서 자동 실행, 창을 닫아도 트레이에 남는다.
- 자동 실행도 먼저 비교하고, 삭제 수가 자동 한도(기본 50) 이하일 때만 실행. 넘거나 실패하면 멈추고 알림.

## 영향

- `src/shared/cron.ts`, `src/main/schedule/scheduler.ts`, 트레이, 편집 창 "자동 실행" 칸, 목록 "자동" · "자동 멈춤".

## 제약

- 자동 실행도 `runner.execute()`의 같은 검사를 거친다.
- 켠 뒤부터 센다(놓친 차례를 따라잡지 않는다).

## 결정된 것

- 앱 안 스케줄을 먼저, Windows 작업 스케줄러(SR-14)는 2단계 — 사용자 "진행".

## 계획 (한 것)

1. cron 파서(외부 라이브러리 없음) · 스케줄러를 가짜 runner · 시계로 테스트
2. 통합: 실제 rclone 자동 실행 · 한도 초과 멈춤

## 결과

- R2 통과(R1 reviewer: 편집 창이 열린 사이 멈춘 작업을 저장하면 멈춤이 풀림, 비교 중 끄거나 멈춰도 실행 → 저장은 멈춤을 지키고 실행 직전 다시 판단).
- 남은 것: Windows 작업 스케줄러 등록(SR-14) 미구현.
