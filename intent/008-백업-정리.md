# 008 F18 백업 정리

- 작성: Claude (PRD F18, 사용자 "남은거랑 다음후보 다해줘" 2026-10-17) · 상태: 계획
- 관련: SR-04(백업 기본 켬), F12

## 문제

동기화할 때 지우거나 덮어쓴 파일은 대상 드라이브의 `.rclonegui-backup\작업\실행\`(리모트면 `리모트:.rclonegui-backup/…`)에 쌓이기만 한다. 얼마나 쌓였는지 보이지 않고 지우는 방법도 없다. C 드라이브 여유가 적은 사용자에게 문제가 된다.

## 바라는 결과

- 실행 기록 표의 동기화 줄에 **백업 크기**("백업 12 MB")를 보인다(처음 볼 때 읽어 두고 다시 읽지 않음, [새로 고침]).
- 작업 화면 [⋯] 메뉴에 **[오래된 백업 정리]**: 보관 기간(기본 30일, 7 · 30 · 90일 · 직접) → 지울 백업 폴더 목록(실행 시각 · 크기)과 합계 → **체크 확인 뒤** [지우기]. 자동으로 지우지 않는다.
- 지우는 범위는 **그 작업의 백업 폴더 아래 실행 폴더**만(`.rclonegui-backup\<작업 ID>\<실행 ID>`). 다른 경로는 지우지 않는다.

## 영향

- main: 로컬은 `fs.rm`(경로를 실행 기록의 backupDir로만 정하고, 백업 뿌리 아래인지 다시 확인), 리모트는 `rclone purge <리모트 백업 경로>` — **`--dry-run` 없는 rclone 쓰기 명령**이 새로 생긴다(sync/copy는 아님). 크기는 로컬 `fs` 합산, 리모트 `rclone size --json`(읽기 전용).
- 새 IPC: `runs:backup-size`, `backups:plan-cleanup`, `backups:cleanup`(계획 ID와 확인한 개수를 받아야 실행 — execute와 같은 모양).

## 제약

- AGENTS.md 1.2는 sync/copy에 대한 규칙이지만, 지우는 명령이 새로 생기므로 **ADR**로 남긴다(지우는 대상 경로 규칙 · 확인 절차 · 리모트 purge 허용 범위).
- 지울 경로는 화면에서 받지 않는다(실행 ID만 받고 main이 기록에서 경로를 꺼냄). 경로가 백업 뿌리 아래 `작업 ID\실행 ID` 모양이 아니면 거부.
- 지운 뒤 실행 기록의 백업 링크는 "정리됨"으로 표시.
