# intent — 의도 · 계획 문서

사용자가 말한 수정 요구를 **의도(무엇이 왜 필요한가) → 계획(어떻게 증명하며 만들 것인가)** 순서로 적는다.
참고: [The AI-native SDLC playbook](https://claude.com/ko/resources/articles/the-ai-native-sdlc-playbook) — 단계마다 버전 관리되는 산출물을 남기고, 판단이 필요한 결정은 사람이 한다.

## 흐름

1. `intent/NNN-기능.md` — 의도와 계획. **사람이 정할 것**은 "미해결 질문"에 적고, 답을 받기 전에는 그 부분을 만들지 않는다.
2. 구현할 때 `docs/specs/YYYY-MM-DD-*.md` 명세를 쓰고 `feature-pipeline`(구현 → `reviewer` · `app-verifier` 병렬 검증, 최대 3라운드)으로 진행한다.
3. 끝나면 이 표의 상태와 각 문서의 "결과"를 고친다. 계획이 바뀌면 같은 커밋에서 문서도 고친다.
