# 004 --ignore-errors를 백업 없이 쓰기

- 작성: Claude (사용자 질문 2026-10-22) · 상태: **결정 필요** (안전장치 변경)
- 관련: SR-05, ADR 0003, AGENTS.md 1.3(차단 목록: "백업 없는 `--ignore-errors`")

## 질문

"`--ignore-errors` 옵션을 백업 폴더 옵션 선택 없이 단독으로 처리할 수 없는지?"

## 지금 막는 이유

- rclone은 원본을 읽다가 오류가 나면(권한 · 잠긴 파일 · 끊긴 네트워크 드라이브) **대상 삭제를 모두 보류**한다. 읽지 못한 파일을 "원본에 없음"으로 잘못 보고 대상에서 지우는 것을 막는 rclone의 안전장치다.
- `--ignore-errors`는 그 보류를 끈다. 원본 일부를 못 읽은 상태로도 삭제가 진행되어, **원본에 멀쩡히 있는 파일의 대상 사본이 지워질 수 있다**.
- 그래서 지금은 백업 폴더가 켜져 있을 때만 허용한다(지워진 것은 백업에서 되살릴 수 있게). ADR 0003의 결정이고, 이 조합을 줄이는 변경은 ADR이 필요하다(AGENTS.md 1.3).

## 선택지

| 안       | 내용                                                                                                                                                            | 위험                                                                          |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| A (권장) | 지금대로. 백업을 켠 작업에서만 허용. 편집 창 안내 문구만 더 분명히(왜 백업이 필요한지)                                                                          | 없음                                                                          |
| B        | 백업 없이도 허용하되, 체크할 때 경고 확인 창 + 미리보기에 읽기 오류가 있으면 [동기화] 확인 창에 "읽지 못한 파일 N개, 삭제 M개" 강조 + 자동 실행(F10)에서는 금지 | 읽기 오류 + 삭제가 겹치면 되살릴 수 없는 삭제                                 |
| C        | copy 모드에서는 백업 없이 허용(copy는 대상 파일을 지우지 않음), sync에서는 지금대로                                                                             | copy도 덮어쓰기는 함(덮어쓴 파일은 백업 없으면 못 되살림). 다만 지우지는 않음 |

## 미해결 질문 (사람이 정함)

- [ ] A / B / C 중 무엇으로 할지. B · C는 ADR 0003을 고치는 새 ADR과 차단 목록 테스트 변경이 필요하다.

## 계획 (결정 뒤)

- A: 안내 문구만 고친다(006 용어 점검에 포함).
- B 또는 C: ADR 0008 작성 → `command-builder` 검사 · `job-store` 검사 · 스키마 · 편집 창 · 확인 창 · 스케줄러 검사 변경 → 차단 목록 테스트 갱신(약하게 바꾸는 이유를 테스트 이름에) → 통합 테스트(읽기 오류 상황 흉내: 권한 없는 파일) → 두 검증.
