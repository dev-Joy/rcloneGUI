# rcloneGUI 의도 (Intent)

이 문서는 **왜 만드는가**와 **판단이 갈릴 때 무엇을 고르는가**를 적는다. 무엇을 만드는지는 [prd.md](prd.md), 어떻게 작업하는지는
[AGENTS.md](../AGENTS.md)에 있다. 사람과 AI 에이전트가 새 기능을 시작하기 전에 먼저 읽는다.

## 한 줄

손으로 치던 rclone 명령 두 개를, **지워질 것을 먼저 보여주고 확인받은 만큼만 지우는** 앱으로 바꾼다.

## 배경

- 폴더 동기화에 쓰던 GoodSync가 구독 전용으로 바뀌어 쓰지 않게 됐다.
- 지금은 rclone 명령 두 개를 필요할 때 손으로 실행한다. 파일은 WSL 작업 폴더 → 로컬 드라이브 → Google Drive 한 방향으로 흐른다.
- 두 구간이 모두 `sync`라서, 원본에서 사라진 파일은 대상에서도 지워지고 그 삭제가 다음 구간까지 이어진다.
- 명령은 그때그때 만들어 붙여 넣는다. `sync`와 `copy`를 헷갈리거나 `--dry-run`을 빼먹어도 실행 전에 잡아 줄 단계가 없다.

## 풀려는 문제

1. **확인 없이 지워진다.** 경로를 잘못 적거나 원본이 비어 있으면 대상 전체가 삭제 대상이 된다. 원본 폴더 하나를 못 읽었는데
   `--ignore-errors`가 켜져 있으면 대상의 그 폴더가 지워진다.
2. **되돌릴 수 없다.** 로컬 삭제는 휴지통을 거치지 않는다.
3. **사고가 번진다.** 첫 구간의 잘못된 삭제가 두 번째 구간을 타고 백업본까지 간다.
4. **잊는다.** 실행을 잊으면 백업이 늦어진다.

1~3이 먼저다. 4(자동 실행)는 1~3이 믿을 만해진 뒤에 한다. 순서를 바꾸면 사고를 자동으로 퍼뜨리는 도구가 된다.

## 누구를 위한 것인가

개발자 한 사람이 자기 PC에서 쓴다. rclone을 이미 알고, 리모트도 `rclone config`로 만들어 두었다.
여러 사용자, 서버, 로그인, 다른 OS는 대상이 아니다.

## 만드는 방식

- **동기화 엔진은 만들지 않는다.** 무엇을 복사하고 지울지는 전부 rclone이 판단한다. 앱은 명령을 만들고, 미리 보여주고,
  막을 것을 막고, 기록을 남긴다.
- **미리보기와 실행은 같은 명령이다.** 실행은 미리보기에서 `--dry-run`만 뺀 것이어야 한다. 둘이 달라지면 미리보기는 안전장치가 아니다.
- **앱 밖에서도 똑같이 된다.** 앱이 만든 명령을 복사해 터미널에서 실행하면 같은 결과가 나와야 한다. 앱이 고장 나도 손으로 돌아갈 수 있다.

## 판단 기준

기능을 설계하거나 구현하다 갈릴 때 위에서부터 적용한다.

1. **지우는 일은 사람이 본 만큼만.** 삭제는 미리보기에 나온 수를 사람이 확인한 뒤에만, 그 수까지만 일어난다.
   자동 실행도 예외가 아니다 — 자동 한도를 넘으면 멈추고 알린다.
2. **의심스러우면 멈춘다.** 원본이 비었거나, 읽기 오류가 있거나, 미리보기 뒤에 상황이 바뀌었으면 진행하지 않는다.
   "아마 괜찮을 것"으로 넘어가는 경로를 만들지 않는다.
3. **되돌릴 길을 남긴다.** 지우거나 덮어쓰는 파일은 기본으로 백업 폴더에 옮긴다. 백업을 끄는 것은 사용자가 고른 경우뿐이다.
4. **일어날 일을 그대로 말한다.** 버튼과 안내는 "동기화"가 아니라 "대상에 12개 복사, 3개 삭제"처럼 적는다.
   확인하지 못한 것을 확인했다고 보여주지 않는다.
5. **rclone이 하는 일을 다시 구현하지 않는다.** rclone에 옵션이 있으면 그것을 쓴다. 앱이 파일을 직접 복사하거나 지우지 않는다.
6. **편의는 안전 다음이다.** 클릭 한 번을 줄이려고 확인 단계를 없애지 않는다. 안전장치를 약하게 만드는 변경은 사용자에게 먼저 묻고 ADR로 남긴다.

## 하지 않는 것

- 사람 확인 없는 충돌 해결 (양방향 동기화는 `rclone bisync`로 하되, 충돌과 삭제는 미리보기로 보여주고 확인받는다 — 2026-10-14 변경)
- 서버, 계정, 여러 사용자
- 클라우드 계정 연결 화면 (리모트는 `rclone config`로 만든 것을 쓴다)
- macOS · Linux 빌드
- rclone.conf를 읽거나 고치는 일 (경로로만 넘긴다)
- 파일 내용을 앱이 해석하는 일 (rclone의 판단을 보여주기만 한다)

이 목록에 있는 것을 요청받으면, 만들기 전에 이 문서를 먼저 고칠지 사용자와 이야기한다.

## 잘 됐다는 것은

- 실제 두 작업을 앱으로 돌리는 것이 손으로 명령을 치는 것보다 **덜 불안하다.**
- 실행 전에 본 숫자와 실행 결과가 같다.
- 실수로 지운 파일을 백업 폴더에서 찾아 되돌릴 수 있다.
- 앱 없이도 같은 명령을 터미널에서 돌릴 수 있다.

숫자로 된 완료 기준은 [prd.md](prd.md)의 "완료 기준"에 있다.
