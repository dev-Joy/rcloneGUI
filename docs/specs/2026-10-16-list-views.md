# F22 목록 필터 확장 ("기타" 보기)

- 날짜: 2026-10-16
- 요구사항: [prd.md](../prd.md) F22 (P2, v0.3). GoodSync 비교 화면의 "기타" 필터 메뉴를 배치만 참고
- 사용자 "계속 진행해"(2026-10-16): v0.3을 차례로

## 목적

상태 칩(추가 · 변경 · 삭제 · 오류 · 같음)으로는 답하지 못하는 질문에 답한다.

- 이번 비교에 무엇이 들어갔나 → **포함됨**
- 제외 패턴 · 범위 때문에 무엇이 빠졌나 → **제외됨**
- 지난 동기화 뒤 원본에 새로 생긴 파일은 무엇인가 → **새로 생김**
- 실행이 실패 · 중지되었을 때 무엇이 처리되지 않았나 → **아직 실행되지 않음**

## 동작

칩 줄 오른쪽에 "기타" 선택 상자(`<select aria-label="기타 보기">`). 고르면 상태 칩 필터 대신 그 보기를 쓴다. 칩을 누르면 칩 보기로 돌아간다.
작업을 바꾸거나 다른 실행을 열면 칩 보기로 돌아간다. 쓸 수 없는 보기는 선택 상자에서 비활성이고 이유를 옵션 글에 붙인다.

| 보기               | 쓸 수 있는 실행                 | 보여 주는 것                                                                                                                                                                                                                |
| ------------------ | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 포함됨             | 모두                            | 이 실행 목록의 모든 항목(같음 포함, 상태 무관)                                                                                                                                                                              |
| 제외됨             | 성공한 미리보기                 | 필터 없이 읽은 원본 · 대상 파일 목록에서 이 미리보기 목록에 없는 파일. 요청할 때만 main이 계산(아래)                                                                                                                        |
| 새로 생김          | 미리보기, 앞선 실제 동기화 있음 | 이 미리보기의 "추가" 파일 중, 이 미리보기보다 먼저 끝난 마지막 **성공한 실제 동기화**의 미리보기 목록에서 원본 쪽에 있던(추가 · 변경 · 같음 · 오류) 경로가 아닌 것. 대상에서 지워져 다시 복사되는 파일은 새로 생김이 아니다 |
| 아직 실행되지 않음 | 실제 동기화 실행                | 그 실행의 미리보기에서 할 일(추가 · 변경, sync면 삭제)이었는데 실행 목록에 같은 상태로 나오지 않은 파일(없음 · 오류 · 다른 상태). 일어날 일 칸에 "· 처리 안 됨"                                                             |

- 폴더 작업 항목(F25 `isDir`)은 포함됨에만 나온다. 나머지 세 보기는 파일만 본다(삭제 수 · 한도가 파일 기준인 것과 같다).
- 실제 동기화 실행의 combined에도 모든 파일이 상태와 함께 남는다(2026-10-16 통합 테스트에서 확인). 아직 실행되지 않음은 이것과 미리보기 목록을 비교한다.

### 제외됨 계산 (main, `runs:excluded`)

- 입력 `{ jobId, runId }`. 성공한 미리보기만 받는다(`EXCLUDED_UNAVAILABLE`).
- 작업의 지금 설정 지문이 그 미리보기의 `jobHash`와 다르면 거부한다(`RUN_STALE`, "작업 설정이 바뀌었습니다. 다시 비교하세요"). 원본 · 대상 경로가 바뀌었을 수 있다.
- `lsjson <side> -R --files-only`를 필터 파일 **없이** 원본 · 대상에 동시에 띄운다. config · `--skip-links` · `--fast-list`는 F11 목록과 같다. 읽기 전용이고 차단 목록을 거친다(만들 때와 띄우기 직전).
  대상 폴더가 아직 없으면(exit 3, 로컬) 빈 목록으로 본다.
- 결과 = (원본 경로 ∪ 대상 경로) − 이 미리보기의 파일 경로. 항목은 `{ path, source: 크기 · 시각 | null, dest: … | null }`, 경로 순.
- 실행 폴더에 `excluded.json`으로 남겨 다시 열 때는 읽기만 한다. 남긴 결과는 그 미리보기 때 계산한 것이라, 설정 지문 검사보다 먼저 읽는다(설정이 바뀐 뒤에도 그 미리보기의 결과는 그대로 보인다). 같은 실행을 동시에 요청하면 한 번만 계산한다.
- 계산은 지금 디스크를 읽은 결과다. 화면에 "지금 읽은 목록 기준 · 비교 뒤 바뀐 파일은 다를 수 있음"을 적는다.
- `--dump filters`는 쓰지 않는다(SR-09 차단 목록).

### 화면

- 제외됨 · 아직 실행되지 않음 항목은 화면용 표시 `note: "excluded" | "pending"`을 달아 목록 · 트리에 그린다. 일어날 일 칸: 제외됨 "제외됨 · 건드리지 않음", 처리 안 됨 "새로 복사 · 처리 안 됨"처럼 미리보기 문구 뒤에 붙인다.
- 트리의 폴더 요약에는 제외된 파일을 "제외 N"으로 따로 센다(상태 건수에 넣지 않는다).
- 제외됨을 고르면 "제외된 파일을 읽는 중…"을 보이고, 실패하면 알림과 목록 자리에 이유를 보인다.
- 아직 실행되지 않음은 실행이 끝난 뒤에만 고를 수 있다(도는 중에는 대부분이 처리 안 됨으로 보이므로).
- 좁은 창에서는 칩 줄이 다음 줄로 넘어간다. 칩 · 단추 글자는 접지 않는다.

## 안전

- 실행 · 확인 창 · 삭제 수는 바뀌지 않는다. 확인 창은 지금처럼 미리보기의 전체 목록을 받는다(보기와 무관).
- 새 IPC는 실행 ID만 받는다. 경로를 받지 않고, 쓰기 명령을 만들지 않는다. lsjson 인자는 `assertSafeArgs`를 거친다.

## 확인 방법

1. `pnpm run check`, `pnpm run test:int`
2. 화면: 비교 → 기타 "포함됨"(같음까지) → "제외됨"(node_modules 아래 파일) → 동기화 → 원본에 파일 추가 → 비교 → "새로 생김"(새 파일만) → 실행 기록의 실행을 열어 "아직 실행되지 않음"(성공이면 비어 있음).
