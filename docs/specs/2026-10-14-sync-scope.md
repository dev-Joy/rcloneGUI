# F25 동기화 범위 (전체 · 파일만 · 폴더 구조만)와 폴더 작업 미리보기

- 날짜: 2026-10-14
- 요구사항: [prd.md](../prd.md) F25 (P1, v0.2), 사용자 메모 "폴더만 할건지, 파일만 할건지, 전체다 할건지"
- rclone 동작: [rclone-notes.md](../knowhow/rclone-notes.md) 2026-10-14 "폴더 동기화 범위" (P1 ~ P4)

## 목적

작업마다 무엇을 맞출지 고른다.

| 범위                       | 파일              | 원본의 빈 폴더 | rclone 표현                                              |
| -------------------------- | ----------------- | -------------- | -------------------------------------------------------- |
| 파일만 (기본, 지금과 같음) | 맞춤              | 만들지 않음    | (옵션 없음)                                              |
| 전체                       | 맞춤              | 만듦           | `--create-empty-src-dirs`                                |
| 폴더 구조만                | **건드리지 않음** | 만듦           | `--create-empty-src-dirs` + 필터 파일 끝에 `+ */`, `- *` |

그리고 **폴더 작업을 미리보기에 보여준다.** 실험(P1)에서 sync는 지금도 대상에만 있는 빈 폴더를 지우는데,
combined에는 폴더가 나오지 않아 미리보기에 보이지 않았다. 판단 기준 4("확인하지 못한 것을 확인했다고 보여주지 않는다")에 맞게 고친다.

## 결정 (사용자 확인 2026-10-14)

- 기본 범위는 "파일만"(지금과 같음). 예전 작업도 "파일만"으로 읽는다.
- 폴더 작업(만들 폴더, 지울 빈 폴더)은 모든 범위에서 미리보기 목록과 확인 창에 보여준다.

## 동작

### 작업 옵션

- `jobSchema.options.scope: "files" | "all" | "folders"`, `default("files")`. 작업 설정 지문(`jobHash`)에 들어간다.
- 작업 편집 창 라디오 3개:
    - 파일만 — 원본의 빈 폴더는 만들지 않음
    - 전체 — 파일과 원본의 빈 폴더까지
    - 폴더 구조만 — 파일은 그대로 두고 폴더만 만듦
- sync 모드에서는 범위와 상관없이 대상에만 있는 **빈** 폴더가 지워진다는 안내 한 줄(실험 P1 ~ P3). copy는 폴더를 지우지 않는다(P4).

### 명령

- `buildArgs`: `all` · `folders`면 `--create-empty-src-dirs`.
- `buildFilterText(excludes, scope)`: `folders`면 사용자 제외 패턴 뒤에 `+ */`, `- *` 두 줄. 필터는 앞에서부터 먼저 맞는 규칙이 이기므로 제외 패턴이 우선한다.
- 미리보기와 실행은 같은 필터 파일 · 같은 인자(`--dry-run`만 차이). 상세 읽기(F11 lsjson)도 같은 필터를 쓴다(폴더 구조만이면 파일이 없다).
- 새 옵션 `--create-empty-src-dirs`는 차단 목록과 무관하다. `--delete-excluded`는 지금처럼 차단이라, "폴더 구조만"에서 걸러진 파일은 대상에서 지워지지 않는다(P3 확인).

### 폴더 작업 읽기 (main)

- 미리보기(`--dry-run --use-json-log -v`)의 로그 줄 중 `skipped`가 `"make directory"` · `"remove directory"`인 것의 `object`(상대 경로)를 모은다(P3 로그).
- 실제 실행의 로그에서는 메시지 `Made directory…` · `Removing directory`의 `object`를 모은다(실행 결과 표시용).
  실행 로그의 정확한 JSON 형식은 구현 전에 `rclone-probe`로 확인하고 노트에 적는다.
- 실행 폴더에 `dirs.txt`(줄마다 `+ 경로` 만들 폴더, `- 경로` 지울 빈 폴더)로 쓰고, 메타에 `dirs: { make, remove } | null`.
- `readItems`가 `dirs.txt`를 읽어 항목에 더한다: `{ path, status: "add" | "delete", isDir: true }`.
  `countItems`(파일 건수 · 삭제 수 · SR-03 `--max-delete`)는 **폴더 항목을 세지 않는다.** rclone의 `--max-delete`도 파일만 센다.

### 지우기 시도와 실제 결과 (R1 지적, 실험 P6)

- rclone의 `remove directory` / `Removing directory`는 "지우기 시도"다. 필터에 걸린 파일만 든 대상 폴더도 이 로그를 남기지만 실제로는 지워지지 않는다.
- 미리보기의 지우기 항목은 "대상에만 있음 · 비어 있으면 지움", 요약은 "대상에만 있는 폴더 N개(비어 있으면 지움)"로 쓴다.
- 로컬 대상의 실제 실행은 끝난 뒤 각 폴더가 남았는지 확인한다. 사라졌으면 "빈 폴더 지움", 남았으면 `dirs.txt`에 `= 경로`, 항목 상태 `same`, "남김 (파일이 있음)". 메타 `dirs`는 `{ make, remove, kept, verified }`.
- 리모트 대상은 확인하지 않는다(`verified: false`, "지우기 시도 (비어 있을 때만)").

### 화면

- 평면 목록과 트리: 폴더 항목은 배지 "폴더 만듦"(녹색) · "빈 폴더 지움"(빨강). 트리에서는 그 폴더 줄에 배지를 붙인다(폴더 줄이 없으면 만든다).
- [동기화] 문구 · 켜짐 조건: 파일 변경 수에 폴더 작업 수를 더한다. "대상에 폴더 3개 만듦, 빈 폴더 1개 지움"처럼 적는다.
  "폴더 구조만" 작업은 폴더 작업만 있어도 [동기화]가 켜진다.
- 실행 확인 창: 폴더 작업이 있으면 "폴더 N개를 만들고, 비어 있는 폴더 M개를 지웁니다" 한 줄과 목록(최대 500줄).
  빈 폴더 삭제는 파일 손실이 없으므로 삭제 확인 체크(SR-02)에 넣지 않는다. 파일 삭제 확인은 그대로.
- 상태 칩 숫자는 파일만 센다. 폴더 작업은 칩 옆에 "폴더 +3 · −1"로 따로 보인다.

## 안전

- 파일을 지우거나 덮어쓰는 조건은 바뀌지 않는다. SR-01 ~ SR-03의 판단(미리보기, 확인한 파일 삭제 수, `--max-delete`)은 파일 기준 그대로다.
- "폴더 구조만"은 파일을 바꾸지 않는다: 필터 `- *`가 모든 파일을 걸러 내고, `--delete-excluded`는 차단되어 있다. 통합 테스트로 고정한다.
- 대상의 빈 폴더 삭제는 지금도 일어나던 일이고, 이제 미리보기와 확인 창에 보인다. 비어 있는 폴더만 지워지므로 백업 대상이 없다.
- 미리보기 뒤 대상에 파일이 생긴 폴더는 rclone이 지우지 않는다(비어 있지 않음).
- **SR-06 (2026-10-16 사용자 확인, ADR 0006)**: "폴더 구조만"은 파일을 모두 걸러 내 원본 파일 수가 늘 0이므로, 이 범위에서만 빈 원본 차단의 파일 수 검사를 하지 않는다. 원본 폴더 존재 검사는 그대로다.

## 확인 방법

1. `pnpm run check`, `pnpm run test:int`
2. 화면: 빈 폴더가 있는 원본과 대상에만 빈 폴더가 있는 대상으로 범위 3개를 각각 비교 → 폴더 작업이 목록 · 확인 창에 보이고, 실행 결과가 미리보기와 같다 →
   "폴더 구조만"은 대상 파일이 하나도 안 바뀐다 → 기존 작업은 "파일만"으로 보인다.

## 하지 않는 것

- 빈 폴더 삭제를 막는 옵션(필요하면 별도 요청)
- 폴더 수정 시각 맞추기 표시(`set directory modification time`)
