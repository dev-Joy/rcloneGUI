# 작업 목록: 최근 동기화 · 주기 · 다음 실행

- 날짜: 2026-10-17
- 요구사항: [prd.md](../prd.md) "작업 목록 (변경)" — 스케줄 켜짐 표시(F10). GoodSync 왼쪽 목록(최근 동기 일시 · 자동 여부 · 주기)을 배치만 참고
- 사용자(2026-10-17): "goodsync처럼 왼쪽에 동기화목록(최근동기일시, 자동화여부, 주기) 이런거 보이나?" → 부족한 부분 제안에 "해줘"

## 목적

왼쪽 작업 목록만 보고도 언제 마지막으로 **실제로 동기화**했는지, 자동 실행이 어떤 주기로 언제 다음에 도는지 알 수 있게 한다.

## 동작

작업 한 줄은 이름 아래 작은 글씨 두 줄이다(지금은 한 줄).

1. 첫째 줄: 모드 배지(sync · copy) + 최근 실행
    - 도는 중이면 "실행 중"(지금과 같다)
    - 실제 동기화 기록이 있으면 "동기화 10-17 01:52". 그 동기화가 실패 · 취소면 "동기화 실패 10-17 01:52" / "동기화 취소 …"
    - 그 뒤에 비교만 했으면 " · 비교 10-17 02:10"을 덧붙인다
    - 동기화 기록이 없고 비교만 있으면 "비교 10-17 02:10", 아무 기록도 없으면 "실행 기록 없음"
    - 시각은 지금처럼 `MM-DD HH:mm:ss` 형식(`formatDateTime`)
2. 둘째 줄(자동 실행을 켰거나 멈춤일 때만)
    - 켜짐: "자동" 배지 + 주기 + " · 다음 02:30"(오늘이면 시:분, 다른 날이면 `MM-DD HH:mm`). 다음 시각을 아직 모르면(앱을 막 켬, 30초 안) 주기만
    - 멈춤: "자동 멈춤" 배지 + 주기. 다음 시각은 쓰지 않는다. 멈춘 이유는 지금처럼 툴팁
3. 줄 전체 툴팁(title)에 이름 · 최근 실행 · 자동 정보를 줄바꿈으로 모아 둔다(목록 폭이 좁아 말줄임될 때).

### 주기 문구 (`describeSchedule`, 순수 함수 `src/lib/schedule-text.ts`)

- 간격: `everyMinutes`가 1440의 배수면 "N일마다", 60의 배수면 "N시간마다", 아니면 "N분마다"(1이면 "1분마다")
- cron, 흔한 모양만 사람이 읽게:
    - `*/N * * * *` → "N분마다"(60을 나눠 떨어지는 N만. `*/45`는 실제로 :00 · :45라 식 그대로), `M * * * *` → "매시 M분"
    - `M H * * *` → "매일 HH:MM", `M H * * D`(요일 하나, 0~7) → "매주 일/월/…요일 HH:MM", `M H * * 1-5` → "평일 HH:MM"
    - `M H D * *`(날 하나, 1 ~ 28) → "매월 D일 HH:MM"(29 ~ 31일은 없는 달에 돌지 않으므로 식 그대로)
    - 그 밖은 "cron <식>" 그대로

### 다음 실행 시각

- 자동 실행기가 앱을 켠 뒤부터 센 실제 값(`clsScheduler.nextRunAt`)을 쓴다. 화면이 따로 계산하지 않는다(간격은 앱을 켠 때부터 세므로 화면 계산과 다를 수 있다).
- 새 IPC `jobs:next-runs` → `Record<작업 ID, ISO 시각 | null>`. 입력 없음. 목록이 30초마다, 그리고 작업이 바뀌었을 때(`jobs:changed`) 다시 묻는다.

## 안전

- 표시만 바뀐다. 실행 · 자동 실행 판단 · 안전장치와 관계없다. 새 IPC는 읽기 전용이고 입력이 없다.

## 확인 방법

1. `pnpm run check`
2. 화면(임시 프로필): 작업 둘 — 하나는 자동(5분마다), 하나는 cron(`0 3 * * *`) → 목록에 "자동 · 5분마다 · 다음 …"과 "자동 · 매일 03:00 · 다음 …". 비교 → "비교 …", 동기화 → "동기화 …", 다시 비교 → "동기화 … · 비교 …". 자동 멈춤 상태 표시. 좁은 창(886)에서 말줄임과 툴팁.

## 하지 않는 것

- 목록 폭 끌어서 조절
- 다음 실행 시각을 저장해 앱을 다시 켰을 때 이어 세기(지금 자동 실행기 동작 그대로)
