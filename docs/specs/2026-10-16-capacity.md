# F20 용량 표시

- 날짜: 2026-10-16
- 요구사항: [prd.md](../prd.md) F20 (P2, v0.3). GoodSync 화면의 "여유: 468 GB, 전체: 512 GB, 필요함: 5.12 KB"
- 사용자 "진행"(2026-10-16): v0.3을 F20부터

## 이 PC에서 확인한 것 (2026-10-16, rclone v1.75.1)

- `rclone about <경로> --json` → `{"total": …, "used": …, "free": …}`(바이트). 로컬 폴더는 그 폴더가 있는 드라이브, `\\wsl.localhost\Ubuntu\…`는 WSL 가상 디스크의 값이 나온다.
- 없는 경로는 `failed to read disk usage`, exit 1. 대상 폴더가 아직 없을 수 있으므로 로컬은 **드라이브 맨 위**(`D:\`, `\\wsl.localhost\Ubuntu\`)로 묻는다.
- 미리보기(dry-run) JSON 로그의 마지막 `stats.totalBytes`는 옮길 파일 크기의 합이다(실험 A: 25 B).
- 파일 시스템 종류(NTFS 등)는 rclone이 알려 주지 않는다. 표시하지 않는다.

## 동작

### main

- 미리보기가 성공으로 끝나면(F11 상세 읽기와 같은 단계, 같은 큐 안) 원본 · 대상에 `rclone about <뿌리> --json`을 동시에 실행한다.
    - 뿌리: 로컬 드라이브 경로는 `path.parse(경로).root`(`D:\`), `\\wsl.localhost\<배포판>\…`는 `\\wsl.localhost\<배포판>\`, 리모트는 `리모트:`(콜론까지).
    - 인자는 `command-builder.ts`의 `buildAboutArgs`(config 경로 포함, 차단 목록 검사). `shell: false`. 시간 제한 30초.
    - 실패하거나 백엔드가 `about`을 지원하지 않으면 그쪽은 `null`("확인 불가").
- 미리보기의 마지막 통계 `totalBytes`를 "옮길 크기"로 쓴다(이미 진행률로 읽고 있다).
- 메타에 `space: { source: itfSpace | null; dest: itfSpace | null; transferBytes: number } | null`(`default(null)`). `itfSpace = { total, used, free }`(바이트, 백엔드가 주지 않은 값은 null).
- 상세 읽기 옵션(F11)과 관계없이 한다(가볍다). 실행(execute) 기록에는 하지 않는다.

### 화면

- 작업 화면 머리의 원본 · 대상 경로 아래에 한 줄: "여유 468 GB / 전체 512 GB"(없으면 "용량 확인 불가"). 대상 쪽에는 "옮길 크기 5.1 KB"를 덧붙인다.
- 대상 여유 < 옮길 크기면 그 줄을 경고 색으로 하고 "대상 드라이브 여유가 옮길 크기보다 작습니다"를 보인다.
  실행 확인 창에도 같은 경고 한 줄(실행을 막지는 않는다. rclone이 공간이 모자라면 실패하고 그 결과를 보여준다).
- 백업은 대상과 같은 드라이브로 옮기므로(`.rclonegui-backup`) 지우거나 덮어써도 여유가 늘지 않는다. 그래서 삭제 크기는 빼지 않는다.
- 값은 그 미리보기 때의 것이다. 표시 옆에 미리보기 시각 기준이라는 것이 드러나게 "비교 시점"이라고 적는다.

## 안전

- 새 명령 `about`은 읽기 전용이다. 실행 조건(SR-01 ~ SR-11)은 바뀌지 않는다. 경고는 실행을 막지 않는다(판단은 사람이).
- 실패해도 미리보기는 그대로 성공이다.

## 확인 방법

1. `pnpm run check`, `pnpm run test:int`
2. 화면: 비교 → 원본 · 대상 아래 여유 · 전체, 대상에 옮길 크기 → (가능하면 큰 파일로) 여유보다 크게 만들 수 없으면 경고는 단위 테스트로만.
