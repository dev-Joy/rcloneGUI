# F09 체인 실행 · SR-11

- 날짜: 2026-10-16
- 요구사항: [prd.md](../prd.md) F09 (P1, v0.2), SR-11, 시나리오 S2("두 작업을 이어서 한 번에 실행"). 사용자 "진행"(2026-10-16)
- 함께 확인: F10 후속 정리 4건(아래 "함께 바뀐 것")

## 목적

WSL 작업 폴더 → 로컬 드라이브 → Google Drive처럼 이어지는 두 작업을 한 번에 돌린다.
**앞 작업이 실패하거나 막히면 뒤 작업은 실행하지 않는다**(SR-11). 첫 구간의 사고가 다음 구간으로 번지는 것을 막는 것이 이 앱의 목적 3번이다.

## 동작

### 설정

- 이미 있는 `schedule.chainNext`(작업 ID 또는 null)를 쓴다. 작업 편집 "자동 실행" 칸 아래 "이 작업이 성공하면 이어서" 선택(없음 + 다른 작업들).
- 저장 검증(main, `job-store.save`): 자기 자신 금지(있음), **고리 금지**(A → B → A처럼 돌아오면 거부, 한국어 메시지), 없는 작업 ID 금지.
- 작업을 지우면 그 작업을 가리키던 `chainNext`를 비운다(있음).

### 자동 실행에서 (F10 스케줄러)

- 앞 작업의 자동 실행이 **실행 성공** 또는 **바뀔 것 없음**으로 끝나면, 이어지는 작업을 같은 자동 흐름(SR-10: 미리보기 → 검사 → `execute()`)으로 바로 돌린다. 뒤 작업의 판단은 **뒤 작업의 자동 한도**로 한다.
- 다음이면 이어서 돌리지 않는다(SR-11):
    - 앞 작업이 멈춤(실패 · 오류 · 빈 원본 · 한도 초과) 또는 건너뜀(이미 실행 중 등)
    - 뒤 작업의 자동 실행이 멈춰 있음(`paused`). 뒤 작업이 `schedule.enabled`가 꺼져 있어도 체인으로는 돈다(체인을 건 것이 곧 자동 실행 허락). 단 멈춤은 존중한다.
- 뒤 작업이 멈추면 뒤 작업만 멈춘다(앞 작업은 이미 끝났다). 알림에 "(A에 이어서)"를 붙인다.
- 한 번의 체인에서 같은 작업을 두 번 돌리지 않는다(저장 검증이 고리를 막지만, 실행 중에도 방문 집합으로 한 번 더 막는다). 체인 길이는 최대 10.

### 수동 실행에서

- 사람이 [실행]으로 앞 작업을 성공시키면, 결과 배너에 "[이어서: <뒤 작업> 비교]" 단추를 보인다. 누르면 뒤 작업을 고르고 비교를 시작한다.
  뒤 작업의 실행은 사람이 평소처럼 확인 창에서 한다(수동 체인은 사람 확인을 건너뛰지 않는다).
- 앞 작업이 실패 · 취소면 단추를 보이지 않는다.

## 안전

- 뒤 작업도 `runner.execute()` 하나로만 실행되고 그 검사를 모두 거친다. 자동이면 뒤 작업의 자동 한도, 수동이면 사람 확인.
- SR-11: 앞이 성공(또는 바뀔 것 없음)일 때만 뒤로 간다. 의심스러우면 멈춘다.
- 같은 대상 동시 1개(SR-08)는 runner 큐가 그대로 지킨다.

## 함께 바뀐 것 (F10 후속 정리, R2 확인 필요 반영)

1. 자동 실행을 끈 채 틀린 cron이 남아 있으면 화면도 [저장]을 막고 이유를 보인다(main과 같은 기준).
2. 스케줄러가 멈추는 중에 또 실패하면 던지지 않고 건너뛴다(처리되지 않는 오류 방지, 테스트).
3. [다시 켜기] 뒤 트레이 상태를 바로 갱신한다.
4. 편집 창 "자동 실행" 칸에 멈춤 안내("저장해도 풀리지 않습니다 … [다시 켜기]").

## 확인 방법

1. `pnpm run check`, `pnpm run test:int`
2. 화면: 작업 A(1분마다 자동) → B 체인 → A 자동 실행 뒤 B가 "자동"으로 이어서 돈다 → A의 대상에 한도 넘는 삭제를 만들면 A가 멈추고 B는 돌지 않는다.
3. 수동: A [실행] 성공 → 배너의 [이어서: B 비교] → B 비교 · 확인 · 실행.
4. 편집 창에서 B → A 체인을 걸려 하면(A → B가 있을 때) 거부.

## 하지 않는 것

- 체인 전체를 한 번에 미리 보여주는 화면, 병렬 실행, 앱이 꺼져 있을 때 체인(F10 2단계)
