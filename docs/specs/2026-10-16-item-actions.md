# F23 항목별 동작 · SR-13

- 날짜: 2026-10-16
- 요구사항: [prd.md](../prd.md) F23 (P2, v0.3), SR-13. GoodSync 비교 화면의 행별 방향 표시와 항목 우클릭을 배치만 참고
- 사용자 "계속 진행해"(2026-10-16): v0.3을 차례로

## 목적

비교 결과의 각 줄에서 무슨 일이 어느 쪽으로 일어나는지 한눈에 보이게 하고, 특정 파일 · 폴더를 이번 실행에서만 빼고 동기화할 수 있게 한다.
뺀 뒤에는 반드시 다시 비교해서 확인한 목록으로만 실행한다(SR-13).

## 동작

### 방향 표시

일어날 일 칸의 배지 앞에 기호를 둔다. 추가 · 변경 `→`(원본 → 대상), sync 삭제 `✕`(대상에서 지움), 같음 `=`, 오류 `!`. copy의 "대상에만 · 그대로 둠", 폴더 작업 · 제외됨은 기호 없음.
기호는 `aria-hidden`이고 배지 글이 뜻을 전한다.

### 이번 실행에서 빼기

- 미리보기 목록(평면 · 트리)의 파일 줄 · 폴더 줄에서 오른쪽 클릭(또는 키보드 메뉴 키)하면 작은 메뉴: **이번 실행에서 빼기**, **경로 복사**.
  미리보기가 아닌 실행 기록, 제외됨 · 아직 실행되지 않음 표시 줄, 같음 · 오류 줄에서는 "빼기"가 없다(경로 복사만).
- 뺀 항목은 작업의 `skip`(상대 경로 목록, 폴더는 끝에 `/`)에 저장한다. 최대 200개, 한 줄 1024자.
- 필터 파일 맨 앞에 붙인다(사용자 제외 패턴 · 범위 규칙보다 먼저). 파일은 `- /<경로>`, 폴더는 `- /<경로>/`와 `- /<경로>/**`.
  rclone 글롭 특수 문자 `\ * ? [ ] { }`는 앞에 `\`를 붙인다(rclone-notes 2026-10-16 F 실험).
- 작업 화면 위에 "이번 실행에서 뺀 항목 N개" 안내와 항목별 [✕ 되돌리기], [모두 되돌리기]. 실제 동기화가 **성공하면** main이 비운다.
- 실패 · 취소한 실행 뒤에는 그대로 남는다. 자동 실행(F10) · 체인(F09)도 같은 필터로 돈다.

### 저장 · IPC

- `jobSchema.skip: string[]`(`default([])`). 편집 창 저장(`jobs:save`)은 `skip`을 바꾸지 않는다(저장된 값을 지킨다, `paused`와 같은 방식).
- `jobs:set-skip` `{ jobId, skip }` → 작업. 바꾸면 `jobs:changed`.
- 실행 설정 지문(`runSettingsOf` → `jobHash`)에 `skip`을 넣는다(비어 있으면 넣지 않아 기존 지문은 그대로).

## 안전 (SR-13)

- 빼거나 되돌리면 지문이 바뀌므로 그 전 미리보기로는 실행할 수 없다. main의 `execute()` 지문 검사가 막고, 화면도 [동기화]를 끈다.
- 뺀 항목은 필터 제외라 sync에서도 대상의 그 파일을 지우지 않는다(`--delete-excluded`는 차단 목록에 있다).
- 실행 뒤 비우기는 실행을 시작할 때의 `skip`과 지금 값이 같을 때만 한다(실행 중에 사람이 바꾼 값은 덮지 않는다).
- 새 IPC는 작업 ID와 상대 경로 목록만 받는다. 경로는 필터 줄로만 쓰고 파일을 열지 않는다. 줄바꿈 · 앞 `/` · 빈 값은 거부한다.

## 확인 방법

1. `pnpm run check`, `pnpm run test:int`
2. 화면: 비교 → 변경 파일 오른쪽 클릭 → 이번 실행에서 빼기 → [동기화] 꺼짐 → 다시 비교 → 그 파일이 목록에서 빠지고 제외됨에 보임 → 동기화 → 대상의 그 파일은 그대로, 안내가 사라짐.

## 하지 않는 것

- 탐색기에서 열기(화면이 경로를 열게 하는 채널은 만들지 않는다)
- 여러 줄을 골라 한 번에 빼기
- bisync 충돌 방향 고르기(F14 이후)
