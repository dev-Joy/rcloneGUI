# 진행 표시: 평균 속도와 남은 시간

- 날짜: 2026-10-17
- 요구사항: [prd.md](../prd.md) F05(진행률 표시)의 개선. 2026-10-16 Google Drive 실사용에서 사용자가 "확인 0/0 · 전송 8/80 · 160 MB / 493 MB · 5.7 KB/s · 남은 시간 16시간 39분"을 보고 속도가 맞는지 물음
- 사용자 "ㅇㅇ 시작해"(2026-10-17)

## 목적

진행 표시의 속도와 남은 시간이 실제와 크게 다르게 보이지 않게 한다.
rclone의 `stats.speed`는 최근 몇 초 기준이라, Drive가 다 올린 큰 파일을 서버에서 마무리하는 동안(파일이 100%에서 1~3분 멈춤) 0에 가깝게 떨어지고, `eta`도 그 속도로 계산돼 수십 시간이 된다.
실제 로그(fixture `log-d-drive-stats.jsonl`): 179초 시점 `speed` 5 KB/s · `eta` 68252초인데, 지금까지 평균은 939 KB/s, 평균으로 남은 시간은 약 6분.

## 동작

- 진행 줄의 속도는 **평균** `bytes / elapsedTime`(지금까지 보낸 양 ÷ 지난 시간)으로 쓴다: "평균 917 KB/s".
  지난 시간이 1초 미만이거나 보낸 양이 0이면 속도를 쓰지 않는다.
- 남은 시간은 평균 속도로 계산한다: `(totalBytes − bytes) / 평균`. "남은 시간 약 6분 12초". 평균을 모르면 쓰지 않는다. 다 보냈으면(bytes ≥ totalBytes) 쓰지 않는다.
- rclone의 순간 속도 · eta는 화면에 쓰지 않는다.
- 전송 중인 파일 가운데 100%에 이른 파일이 있으면 "다 보낸 파일 N개를 마무리하는 중"을 덧붙인다(2026-10-17 정정: 로컬에서도 작은 파일이 많으면 잠깐 100%로 남아 "리모트가"는 맞지 않음)(Drive는 업로드 뒤 서버 처리가 끝날 때까지 기다린다).
- 그 밖의 칸(확인 · 전송 · 바이트 · 삭제 · 오류)과 진행 막대는 그대로다.

## 안전

- 표시만 바뀐다. 실행 · 확인 창 · 삭제 수 · 안전장치와 관계없다. rclone 인자도 바뀌지 않는다.

## 바꿀 파일

| 파일                                          | 변경                                                                                                |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `src/main/parsers/json-log.ts`                | stats에서 `elapsedTime`, `transferring[].percentage`를 읽어 `elapsed` · `finishing`(100%인 파일 수) |
| `src/shared/types.ts`                         | `itfProgress.elapsed` · `finishing`                                                                 |
| `src/lib/format.ts`                           | `averageRate(progress)` → `{ speed, eta }` (순수 함수)                                              |
| `src/pages/JobRunBanner.tsx`                  | 진행 줄에 평균 속도 · 평균 남은 시간 · 마무리 안내                                                  |
| `tests/fixtures/log-d-drive-stats.jsonl` (새) | 실제 Drive 업로드 로그의 stats 줄 3개(파일 이름 · 경로는 중립적으로 바꿈)                           |
| 테스트                                        | 파서(fixture), averageRate(경계값), 기존 log-a fixture 회귀                                         |

## 확인 방법

1. `pnpm run check`, `pnpm run test:int`
2. 화면: 큰 파일 여러 개로 로컬 동기화를 돌려 진행 줄에 "평균 … /s · 남은 시간 약 …"이 보이고, 끝날 때 값이 튀지 않는지 본다. Drive 마무리 안내는 fixture 단위 테스트로 확인한다(실제 Drive는 검증에서 쓰지 않는다).

## 하지 않는 것

- 최근 N초 이동 평균 같은 다른 속도 계산
- 파일별 진행 목록 표시
- 남은 시간을 실행 기록에 남기기
