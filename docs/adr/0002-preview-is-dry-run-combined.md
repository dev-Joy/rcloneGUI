# 0002 미리보기는 `--dry-run --combined`, 실행은 같은 인자에서 `--dry-run`만 뺀다

- 상태: 채택 (2026-10-11)

## 배경

미리보기가 보여준 것과 실제 실행이 달라지면 미리보기는 안전장치가 되지 못한다.

## 결정

- 미리보기와 실행은 `CommandBuilder`의 같은 인자에서 출발한다. 미리보기에는 `--dry-run`만, 실행에는
  `--max-delete <확인한 삭제 수>`와 `--backup-dir`만 더한다. 이 관계는 단위 테스트로 고정한다.
- 실행은 `RcloneRunner.execute()`로만 시작하고, 다음을 모두 만족해야 한다: 성공한 미리보기가 그 작업의 가장 최근 실행이다,
  끝난 지 30분 이내다, 작업 설정 지문(`jobHash`)이 같다, 원본이 비어 있지 않다, 확인한 삭제 수가 미리보기와 같다.
- 결과 목록은 `--combined` 파일을 읽는다. 재시도와 겹치면 줄이 중복되므로 `--retries 1`을 준다.

## 버린 대안

- `rclone check --combined`로 따로 비교: 필터·옵션이 sync와 어긋날 수 있고 실행이 한 번 더 든다.
  v1.75.1의 `sync`가 `--combined`를 직접 지원한다.
- 텍스트 로그 파싱: 형식이 버전에 따라 바뀐다.

## 결과

- 미리보기와 실행 사이에 원본·대상이 바뀌면 삭제는 한도에서 멈추지만(exit 7), 추가·변경은 그대로 진행된다.
  이 경우 덮어쓴 파일은 백업 폴더에 남는다.
- `--combined`가 없는 오래된 rclone은 쓸 수 없다. 시작할 때 `sync --help`로 검사한다.
