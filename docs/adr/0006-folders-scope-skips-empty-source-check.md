# 0006 "폴더 구조만" 범위에서는 빈 원본 차단(SR-06)의 파일 수 검사를 하지 않는다

- 상태: 채택 (2026-10-16, 사용자 확인)
- 관련: [prd.md](../prd.md) SR-06, F25, 명세 [2026-10-14-sync-scope.md](../specs/2026-10-14-sync-scope.md)

## 배경

SR-06은 미리보기에서 원본 파일 수(`+` · `*` · `=`)가 0이면 실행을 막는다. 경로를 잘못 적었거나 원본이 비어 있을 때
sync가 대상의 파일을 모두 지우는 사고를 막기 위한 것이다(실험 K).

F25의 "폴더 구조만" 범위는 필터 끝에 `+ */`, `- *`를 붙여 **모든 파일을 걸러 낸다.** 그래서 combined가 늘 비고 원본 파일 수가 늘 0이다.
SR-06을 그대로 적용하면 이 범위는 항상 차단되어 쓸 수 없다.

## 결정

- 작업의 범위가 `folders`일 때만 미리보기의 빈 원본 판정(`blocked: "EMPTY_SOURCE"`)을 하지 않는다 (`runner.ts`의 `emptySource`).
- 원본 폴더가 있는지 확인하는 검사(`f_AssertSourceDirectory`, 실험 J)는 범위와 상관없이 그대로 한다.
- `files` · `all` 범위의 SR-06은 바뀌지 않는다.

이 범위에서 SR-06이 막으려는 사고가 일어날 수 없는 근거:

1. 필터 `- *`가 모든 파일을 걸러 내고, 걸러 낸 파일을 지우는 `--delete-excluded`는 차단 목록(SR-09)에 있다. 그래서 rclone은 파일을 복사 · 덮어쓰기 · 삭제하지 않는다(실험 P3, 통합 테스트 "폴더 구조만은 파일을 하나도 바꾸지 않고 폴더만 만든다").
2. 이 범위에서 지워질 수 있는 것은 대상에만 있는 **빈 폴더**뿐이다. rclone은 대상에만 있는 폴더를 모두 "지우기 시도"(로그 `remove directory`)하지만 비어 있지 않으면 지우지 못하고 남긴다(실험 P6: 필터에 걸린 파일만 든 폴더도 폴더와 파일이 남는다). 미리보기와 확인 창은 이것을 "대상에만 있는 폴더(비어 있으면 지움)"로 보여주고, 로컬 대상은 실행 뒤 실제로 지워졌는지 확인해 "지움" / "남김"으로 나눈다(F25 R2).
3. 실행은 다른 범위와 같이 미리보기 → 확인 → `--max-delete`(파일 0개로 고정) 순서를 거친다. SR-01 ~ SR-03은 그대로다.

## 버린 대안

- 다른 검사로 대체("원본에 폴더가 하나도 없는데 대상의 빈 폴더를 지우려 하면" 차단): 빈 폴더 삭제는 되돌릴 데이터가 없고 확인 창에 이미 보이므로, 검사를 더해도 막는 사고가 없다. 판정 조건만 늘어난다.
- "폴더 구조만" 범위 빼기: 사용자 요청(메모 "폴더만 할건지")을 충족하지 못한다.

## 결과

- 원본 경로를 잘못 적은 "폴더 구조만" 작업은 막히지 않고, 대상의 빈 폴더를 지우는 미리보기가 나올 수 있다. 확인 창의 폴더 목록으로 알아볼 수 있다.
- 범위를 `folders`에서 다른 값으로 바꾸면 작업 설정 지문이 바뀌어 이전 미리보기는 무효가 되고, 다시 비교할 때 SR-06이 적용된다.
