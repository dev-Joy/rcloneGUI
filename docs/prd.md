# rcloneGUI PRD (제품 요구사항)

rclone 기반 폴더 비교·동기화 데스크톱 앱 (Windows). **무엇을** 만드는지와 **어디까지 됐는지**를 적는다.
왜 만드는지와 판단 기준은 [intent.md](intent.md), 작업 규칙은 [AGENTS.md](../AGENTS.md).

- 원본 기획서: 2026-10-09 (7일 MVP)
- 상태 기준일: 2026-10-12
- 요구사항의 상태를 바꾸면 이 문서의 표를 고친다 (`feature-pipeline`의 마무리 단계).

## 1. 목표

1. 지금 쓰는 두 작업(WSL 작업 폴더 → 로컬 드라이브, 로컬 드라이브 → Google Drive)을 앱에 등록하고 버튼으로 실행한다.
2. 실행 전에 추가 · 변경 · 삭제될 파일을 원본/대상 비교 화면으로 보여준다.
3. 대량 삭제 사고를 막는 안전장치(삭제 확인, 삭제 한도, 백업 폴더)를 기본으로 켠다.
4. 앱이 켜져 있는 동안 정해진 간격으로 자동 실행하고 두 작업을 순서대로 잇는다. (P1)

## 2. 사용자와 환경

- 사용자: 개발자 1명, 자기 PC
- OS: Windows 11. 원본은 `\\wsl.localhost\…` 경로일 수 있다
- 전제: rclone이 설치돼 있고(`sync --combined` 지원 버전), 클라우드 리모트는 `rclone config`로 만들어져 있다
- 범위 밖: 양방향 동기화, 서버 · 로그인, 계정 연결 화면, macOS · Linux, 실시간 파일 감시(P2로 미룸)

| 화면        | 요소                                                                                                     | 상태 |
| ----------- | -------------------------------------------------------------------------------------------------------- | ---- |
| 작업 목록   | 이름, 모드, 마지막 실행 시각과 결과 색 점, [+ 새 작업]                                                   | 구현 |
| 비교 결과   | [비교] [동기화] [중지], 요약 칩(누르면 필터), 원본 · 일어날 일 · 대상 3열(가상 스크롤), 같음은 기본 숨김 | 구현 |
| 작업 편집   | 이름, 원본 · 대상(폴더 선택 또는 리모트:경로), 모드(sync는 경고), 제외 패턴, 옵션, 백업                  | 구현 |
| 실행 확인   | "삭제 N개를 포함해 M개 파일이 바뀝니다", 삭제 목록, 백업 안내, 확인 체크, [실행]                         | 구현 |
| 진행 · 결과 | 진행률(확인 · 전송 · 바이트 · 남은 시간), [중지], 끝나면 결과와 오류                                     | 구현 |
| 실행 기록   | 실행 목록(시각 · 종류 · 결과 · 건수), 그때의 목록 · 로그 · 백업으로 이동                                 | 구현 |
| 설정        | rclone.exe 경로와 상태, rclone.conf 경로, 백업 위치 규칙                                                 | 구현 |

상태 표시 규칙: 같은 기호라도 copy와 sync에서 대상에 일어나는 일이 다르므로 목록에는 "일어날 일"을 적는다.

| combined | 화면        | copy            | sync                      |
| -------- | ----------- | --------------- | ------------------------- |
| `+`      | 추가 (녹색) | 새로 복사       | 새로 복사                 |
| `*`      | 변경 (주황) | 원본으로 덮어씀 | 원본으로 덮어씀           |
| `-`      | 삭제 (빨강) | 그대로 둠       | 삭제 → 백업               |
| `=`      | 같음 (회색) | 변화 없음       | 변화 없음                 |
| `!`      | 오류 (빨강) | 확인 필요       | 확인 필요, 삭제 전체 보류 |

## 7. 기획서와 다르게 만든 점

- copy 실행에도 `--backup-dir`를 넣는다 (copy도 `*` 파일을 덮어쓴다).
- 미리보기는 "가장 최근 실행"일 때만 유효하다 (같은 미리보기로 두 번 실행하지 못한다).
- IPC 채널을 더 두었다: `runs:items`, `run:command`, `settings:*`, `app:*`. `run:execute` 입력에 `jobId`가 있다.
- 실행 기록의 백업 폴더 크기 표시는 넣지 않았다 (F18과 함께).

## 8. 완료 기준 (v0.1.0)

아래가 모두 체크되면 실사용을 시작한다. 하나라도 남으면 그 항목을 고칠 때까지 손으로 치는 rclone을 함께 쓴다.
"임시 폴더"는 테스트나 `drive-app`으로 확인했다는 뜻이고, **실제 두 작업으로는 아직 하나도 확인하지 못했다.**

기능

- [ ] 실제 두 작업을 앱에 등록했고, 앱을 다시 켜도 그대로 있다 — 저장 · 재시작은 임시 폴더로 확인
- [ ] 미리보기 건수가 같은 옵션의 CLI `--dry-run` 결과와 일치한다 — 임시 폴더로 확인
- [ ] 실행 후 다시 미리보기하면 같음만 남는다 — 임시 폴더로 확인
- [ ] 생성된 명령을 복사해 터미널에서 실행하면 같은 결과가 나온다 — 미확인
- [ ] 실행 중 [중지]를 누르면 rclone이 끝나고 기록에 "취소"로 남는다 — 대기 중 취소만 확인

안전

- [ ] 삭제가 있는 sync는 확인 창을 거치지 않고는 실행되지 않는다 — 임시 폴더로 확인
- [ ] 미리보기 뒤 지울 파일이 늘면 삭제 한도에 걸려 멈춘다 — 임시 폴더로 확인
- [ ] 지우거나 덮어쓴 파일이 백업 폴더에 원래 구조로 남는다 — 임시 폴더로 확인
- [ ] 원본 경로가 없거나 비어 있으면 실행이 막힌다 — 임시 폴더로 확인
- [ ] 기본 생성 명령에 `--ignore-errors`가 없다 — 단위 테스트로 확인

품질

- [x] `pnpm run check`와 통합 테스트가 통과한다
- [x] AGENTS.md, CHANGELOG, rclone-notes.md가 최신이다

P1 (했다면)

- [ ] 설치본으로 설치해 실행된다
- [ ] 30분 간격 자동 실행이 2회 이상 정상이고, 삭제 한도를 넘기면 스스로 멈춘다
- [ ] 체인에서 앞 작업이 실패하면 뒤 작업이 실행되지 않는다

| 원본 폴더 읽기 실패 + `--ignore-errors` (최신 rclone) | 삭제로 이어질 수 있음        | v1.60.1에서만 확인. `rclone-probe`로 재확인 필요       |
| 큰 트리에서 미리보기                                  | 화면 멈춤, 메모리            | 미측정. combined는 파일로 받아 읽고 목록은 가상 스크롤 |
| 설치본과 pnpm의 `node_modules` 구조                   | 설치본이 안 만들어질 수 있음 | F12에서 확인                                           |
